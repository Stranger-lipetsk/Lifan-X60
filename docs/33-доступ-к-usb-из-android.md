# Исследование доступа к USB и установщику без перепрошивки

Основа анализа — проверенный по SHA-256 `stock/x60_2021.7z`. В опубликованном
пользователем `рабочая-с-лаунчером/system.img` все исходные обычные файлы
совпадают по содержимому с этим stock; добавлена копия Launcher2 APK. См.
`docs/32-рабочая-с-лаунчером-и-wifi.md`. Отчёт статической трассы:
`reports/stock-file-access.txt`. Состояние Android на устройстве и наличие
носителей из образа не определяются.

## Найдено

1. «Загрузки», которые пользователь открыл из лаунчера, вызывают
   `android.provider.action.MANAGE_ROOT` для корня загрузок, а не гарантированно
   для всей файловой системы. Пользователь увидел пустой список и единственный
   пункт «Таблица» в меню. Это не доказывает, что USB или внутренняя память
   пустые. В коде есть отправка APK-загрузок установщику, но добавление файла
   на USB само по себе не создаёт проверенную запись загрузки.
2. В `DocumentsUI` есть разные режимы: выбор файла возвращает результат
   вызывающему приложению, а режим управления документами может отправлять
   отдельный `ACTION_VIEW`. Доступный с экрана вызов режима управления USB и
   совместимость полученного URI с PackageInstaller пока не установлены.
3. `CertInstaller` в этом образе вызывает системный выбор документа, но
   передаёт фильтр для сертификатов/PKCS#12 и обрабатывает выбранное как
   сертификат. Это **не установщик APK**; переименовывать APK в сертификат,
   выбирать неизвестные сертификаты и устанавливать их нельзя.
4. По литералу `android.provider.action.MANAGE_ROOT` проверено 52 APK/ZIP в
   `/system/app` и `/system/priv-app`, включая Launcher2 без расширения. Он
   найден в DocumentsUI и DownloadProviderUi. Буквальный поиск не исключает
   динамический вызов, другие разделы и другие способы открыть файлы.

## Дополнительный поиск во всех штатных APK

Повторно проверены 52 ZIP/APK из `/system/app` и `/system/priv-app` на
NUL-терминированные DEX-литералы выбора файлов и установки, включая Launcher2
без расширения. `OPEN_DOCUMENT` обнаружен только в CertInstaller и DocumentsUI;
`GET_CONTENT` — в Camera2, DocumentsUI, Music и ElSettings. Это поиск литералов,
а не доказательство вызова, пользовательской доступности или отсутствия
динамических и нативных путей. Важно: прежний поиск без проверки конца строки
ложно совпал с `OPEN_DOCUMENT_TREE` в Navitel; обновлённый поиск различает их.

Проверены методы Camera2 и Music: `CropActivity.pickImage` запрашивает
изображения `image/*`, а найденные в Music совпадения обрабатывают входящий
`GET_CONTENT` и возвращают аудио/видеозаписи; путь к выбору APK они не
подтверждают. Поиск APK MIME также обнаруживает DownloadProvider, Settings,
Navitel, DocumentsUI и установщик, но совпадение внутри APK не доказывает
доступность нужного действия. До сих пор подтверждённого экранного пути
установки с флешки нет. Подробности — `reports/stock-file-access.txt`.

## Идея пользователя: APK в «Загрузки» и прошивка

Пользователь предложил положить APK в папку загрузок и прошить образ. Простое
наличие файла в папке не означает установку. Кроме того, системный экран
«Загрузки» относится к базе DownloadManager: копирование файла в каталог не
доказывает, что там появится запись. Обычная общая папка Download относится к
пользовательскому хранилищу, не к содержимому `/system` в `system.img`; точные
пути и поведение прошивальщика для этой магнитолы отдельно не проверены.

Возможная альтернатива с прошивкой — добавить в копию рабочего system-образа
один отдельный совместимый с Android 4.4.2 файловый менеджер как системное
приложение (`/system/app`), сохранив имеющиеся Home, лаунчер и Navitel. Android
обычно сканирует системные APK при загрузке; работоспособность конкретного APK,
его появление в лаунчере, доступ к USB и запуск установщика на этой магнитоле
нужно проверять и гарантировать заранее нельзя. Приложение и подпись ещё не
выбраны, сборка не создана. Старую панель MirrorLink повторно не использовать.
Ранее тестовый образ зависал до Hibernate, хотя затем такой же system загрузился;
прошивка несёт риск. Полный комплект и поведение записи нужно проверять отдельно;
не обещать, что остальные разделы и пользовательские данные сохранятся. Карты
на SD намеренно не изменять.

## Результат проверки пользователем

Пользователь открыл выбор документа через установку сертификатов и сообщил,
что там видна USB-флешка и APK. На снимках показаны список расположений,
внутренняя память, ещё один носитель без подписи, папки и названия APK;
строки APK выглядят бледными/серыми. По фото нельзя независимо установить,
какой физический носитель соответствует безымянной записи, либо утверждать,
что APK можно выбрать. Выбор и установка APK не подтверждены. Сам экран
предназначен для сертификатов и фильтрует допустимые типы; не выбирать в нём
APK, не переименовывать файлы и не устанавливать сертификаты для обхода фильтра.

## Необязательная безопасная проверка только видимости USB

Проверка поможет выяснить, видит ли системный выбор документа накопитель; она
**не устанавливает приложение и не гарантирует возможность установки APK**.
Проводить только на стоящем автомобиле:

1. Подключить привычную музыкальную USB-флешку. SD-карту Navitel не извлекать.
2. В открытых настройках Android открыть `Wi-Fi` → меню из трёх точек →
   «Дополнительные функции» → «Установка сертификатов». В коде найдена попытка
   открытия выбора документа даже для этого пункта; фактическая доступность
   экрана при выключенном Wi-Fi не подтверждена.
3. Если открылся выбор документов, сфотографировать список расположений слева
   (или открыть его кнопкой меню вверху слева). Не открывать никакие файлы.
   Если появится предложение установить блокировку экрана, сертификат или
   подтверждение изменения, **остановиться**, ничего не подтверждать.
4. Вернуться кнопкой «Назад». На снимке скрыть персональные данные, если они
   отображаются. Не форматировать, не извлекать и не очищать накопители через
   настройки.

Если USB не показан, он всё равно может работать для медиаплеера; если показан,
это не доказывает, что APK будет доступен в этом фильтре или что его можно
будет установить. Для открытия APK нужен отдельный подтверждённый механизм.
Wi-Fi не включать повторно ради этого теста и прошивку не менять.
