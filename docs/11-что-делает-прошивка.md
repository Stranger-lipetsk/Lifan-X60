# Что именно делает прошивка (разбор заводского кода)

Разобрал `build_emmc.sh` из заводского пакета — это скрипт, который запускается
при прошивке. Ниже что он делает по шагам, потому что от этого зависит,
**что произойдёт с твоими картами и лицензией**.

## Порядок операций

```
fool_proofing_operation     — проверка, что прошивка действительно наша
check_essential_files       — есть ли boot.img и system.img
backup_operation            — СОХРАНЯЕТ только config.ini
partition_operation         — ПЕРЕСОЗДАЁТ таблицу разделов (sfdisk)
format_operation            — ФОРМАТИРУЕТ p2, p3, p5, p6, p7
restore_operation           — возвращает config.ini обратно в p6
install_operation           — пишет u-boot, boot.img в p1, system.img в p3
install_navi_operation      — РАСПАКОВЫВАЕТ карты, ЕСЛИ они есть в пакете
```

## Ключевой момент: раздел p7 форматируется всегда

```sh
function format_operation
{
    mke2fs -t ext4 /dev/block/mmcblk0p2      # swap
    mke2fs -t ext4 /dev/block/mmcblk0p3      # system
    mke2fs -t ext4 /dev/block/mmcblk0p5      # data
    mke2fs -t ext4 /dev/block/mmcblk0p6      # el_data / para_fw
    newfs_msdos -F 32 /dev/block/mmcblk0p7   # ← КАРТЫ NAVITEL
}
```

`format_operation` вызывается **безусловно**, до распаковки карт. То есть
`p7` стирается всегда, а обратно карты кладутся только если в пакете
прошивки есть архив `Navngo.tgz_aa` / `_ab` … (`install_navi_operation`
проверяет `if [ -f "$NAVI_MAP_ARCHIVE"_aa ]`).

**Вывод:** наличие архива карт и файла лицензии у тебя на руках — это ещё не
гарантия. Прошивка их с трёт, и вернуть их сможет только сам, если они лежат
в пакете прошивки.

## Что сохраняется само

```sh
function backup_operation
{
    rm -rf /fw_data/backup
    mount -t ext4 /dev/block/mmcblk0p6 /mnt/inand
    cp -f /mnt/inand/config.ini /fw_data/backup/     # ← ТОЛЬКО этот файл
    ...
}
```

Сохраняется **ровно один файл** — `config.ini` (в нём VIN и настройки).
Всё остальное содержимое `p6` (включая `tp_verinfo` и `backup_image/`)
стирается вместе с разделом.

`tp_verinfo` (калибровка тача) восстанавливается не из бэкапа, а
**перегенерируется** из `/proc/gt9xx_ver` при каждой загрузке:

```sh
# general_conf.sh — запускается как сервис в init.rc (строка 562)
rm /mnt/para_fw/tp_verinfo
cat /proc/gt9xx_ver > /mnt/para_fw/tp_verinfo
chmod 444 /mnt/para_fw/tp_verinfo
```

## Про `config.ini` — важно для тебя

Прошивка сохраняет `config.ini` в `/fw_data/backup/`. Но **`/fw_data` — это
раздел внутри `data`**, а `data` (`p5`) тоже форматируется в том же прогоне:

```
format_operation   ← p5 (data) отформатирован
restore_operation  ← читает /fw_data/backup/config.ini
```

По коду восстановление идёт **после** форматирования `p5`. Работает это
только за счёт того, что файл ещё висит в кеше ядра и физически не затёрт.
Это недокументированная хрупкость заводской реализации — обычно срабатывает,
но полагаться на неё как на единственную защиту не стоит.

## Вывод: минимальный бэкап всё-таки нужен

| Данные | Судьба при прошивке | Нужна копия? |
|---|---|---|
| `config.ini` (VIN, настройки) | сохраняется сам в `/fw_data/backup` → возвращается в `p6` | желательно (хрупко) |
| `tp_verinfo` (калибровка тача) | перегенерируется из `/proc/gt9xx_ver` | нет |
| **Карты Navitel (`p7`)** | **форматируется**, возвращаются только из пакета прошивки | **да, если не в пакете** |
| **Файл лицензии** | если он на `p7` — стирается; если на `p6` — тоже стирается | **да, если не в пакете** |
| Установленные приложения, Wi-Fi/BT | стираются (`p5`, `p6` форматируются) | да, если важно |

### Что сделать перед прошивкой (5 минут, не 30)

```bash
# 1. скопировать карты и лицензию КУДА-НИБУДЬ вне p7 и p6
adb shell su -c "mkdir -p /storage/extsd/keep"
adb shell su -c "cp -r /storage/emmc_data/* /storage/extsd/keep/ 2>/dev/null"

# 2. сохранить config.ini и tp_verinfo (страховка от хрупкости restore)
adb shell su -c "cp /mnt/para_fw/config.ini /storage/extsd/keep/"
adb shell su -c "cp /mnt/para_fw/tp_verinfo /storage/extsd/keep/"

# 3. забрать на компьютер
adb pull /storage/extsd/keep ./keep
```

Этого достаточно. Полный дамп разделов (`tools/backup-device.sh`) нужен только
если хочешь уметь вернуть систему **без** перепрошивки.

## Про SD-карту при прошивке

`build_emmc.sh` форматирует `p2`–`p7`, но сам **`/fw_data` не удаляет** —
файлы прошивки на флешке остаются. Практического вреда в этом нет: следующий
запуск всё равно заново создаёт разделы и пишет образы. Но если хочешь
чистый цикл — после прошивки удали `boot.img` и `system.img` с флешки, тогда
ГУ не предложит обновиться повторно.

## Ещё одна находка: у прошивки есть предохранитель

```sh
fool_proofing_operation
```

Эта функция (вызывается первой) проверяет, что прошивка предназначена именно
для этой модели. Значит случайно «чужая» прошивка не начнёт писать разделы.
Полезно знать: если прошивка не стартует — скорее всего сработал этот
предохранитель, а не сломалось железо.
