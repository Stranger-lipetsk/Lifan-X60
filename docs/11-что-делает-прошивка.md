# Что именно делает прошивка (разбор заводского кода)

Разобрал `build_emmc.sh` и `fstab` из заводского пакета. Ниже — что происходит
при прошивке **по коду**, а не по догадкам.

## Порядок операций

```
fool_proofing_operation     — проверка, что прошивка от этой модели
check_essential_files       — есть ли boot.img и system.img
backup_operation            — СОХРАНЯЕТ config.ini на SD-карту прошивки
partition_operation         — ПЕРЕСОЗДАЁТ таблицу разделов eMMC (sfdisk)
format_operation            — ФОРМАТИРУЕТ p2, p3, p5, p6, p7 на eMMC
restore_operation           — возвращает config.ini обратно в p6
install_operation           — пишет u-boot, boot.img в p1, system.img в p3
install_navi_operation      — РАСПАКОВЫВАЕТ карты, ЕСЛИ они есть в пакете
```

## Куда прошивка вообще пишет

Только в **eMMC** (`/dev/block/mmcblk0`) и читает с **SD-карты с прошивкой**.
Проверено: во всём `build_emmc.sh` нет ни одного обращения к `mmcblk1`
(внешняя SD-карта) или `extsd`. Все адреса записи:

```
/dev/block/mmcblk0boot0   ← u-boot
/dev/block/mmcblk0p1      ← boot.img
/dev/block/mmcblk0p2      ← swap (если есть в пакете)
/dev/block/mmcblk0p3      ← system.img
/dev/block/mmcblk0p5      ← данные (tar, если есть в пакете)
/dev/block/mmcblk0p6      ← para_fw / config.ini
/dev/block/mmcblk0p7      ← карты Navitel (форматируется)
```

## Ключевое: что монтируется в режиме прошивки

`fstab` в режиме прошивки (`reports/deep2/update/fstab.el_imx6_solo_v2`):

```
/dev/block/mmcblk1p1                             /fw_data     vfat   rw    wait
/devices/platform/fsl-ehci.1/usb2/2-1/2-1.1      /mnt/media_rw/usb1   vfat  ...
/devices/platform/fsl-ehci.1/usb2/2-1/2-1.2      /mnt/media_rw/usb2   vfat  ...

#/devices/platform/sdhci-esdhc-imx.3/mmc_host/mmc1 /mnt/media_rw/extsd   ← ЗАКОММЕНТИРОВАН
```

Отсюда три вывода:

1. **`/fw_data` — это SD-карта с прошивкой** (`mmcblk1p1`), а не раздел eMMC.
   Значит `config.ini` сохраняется на флешку, которая форматированием eMMC
   не затрагивается. **Сохранение надёжное** (в прошлой версии этого файла я
   ошибочно написал, что `/fw_data` лежит внутри `data` — это неверно).
2. **Слот SD занят прошивкой**, `extsd` в режиме прошивки отключён.
   Вторую карту (с картами и лицензией) в слот SD вставить нельзя —
   только в **USB-порт** (`usb1` / `usb2` работают).
3. Внешние накопители прошивка только монтирует, но **не форматирует**.

## Что реально пострадает, а что нет

| Данные | Где лежат | Судьба | Копия нужна? |
|---|---|---|---|
| Карты и лицензия **на отдельной карте в USB** | `usb1` / `usb2` | **не трогаются** — прошивка в них не пишет | нет |
| Карты **на внутреннем `p7`** | `mmcblk0p7` | **стираются** (`newfs_msdos -F 32`) | да |
| Карты **на SD-карте с прошивкой** | `mmcblk1p1` → `/fw_data` | не форматируются, но `check_essential_files` требует `boot.img` + `system.img` в корне | — |
| `config.ini` (VIN, настройки) | `p6` → копируется на SD прошивки → возвращается | сохраняется надёжно | желательно, но не критично |
| `tp_verinfo` (калибровка тача) | `p6` | перегенерируется из `/proc/gt9xx_ver` при загрузке | нет |
| `backup_image/` (`swap.img`, `data.tar`) в `p6` | `p6` | стирается вместе с разделом | только если хочешь быстрый откат |
| Приложения, Wi-Fi/BT, файлы | `p5`, `p6` | стираются (разделы форматируются) | да, если важно |

## Один реальный риск: USB-порт во время прошивки

Если в пакете прошивки есть **и** `swap.img`, **и** `data.tar`, то
`install_operation` делает так:

```sh
dd if=$SWAPIMAGE of=/dev/block/mmcblk0p2
mount -t ext4 /dev/block/mmcblk0p5 /mnt/media_rw/usb2/     # ← точка USB-накопителя
tar -xvf $DATAIMAGE -C /mnt/media_rw/usb2
```

`p5` монтируется **поверх** точки, где в fstab живёт USB-накопитель. Если в
этот момент в `usb2` вставлена карта с картами:

* при успешном `mount` — карта просто «закрывается» монтированием, файлы целы,
  `tar` распакуется в `p5` (это нормальный сценарий);
* **если `mount` не удался** — `tar -xvf` распакуется **прямо на карту с
  картами**, забив её данными из `data.tar`.

Поэтому безопаснее: **вынуть карту с картами и лицензией на время прошивки**,
вставить после перезагрузки. Один лишний шаг — и риска нет вообще.

Как проверить, есть ли в твоём пакете `swap.img`/`data.tar`: посмотри корень
флешки с прошивкой. Если этих файлов нет, риск нулевой.

## Про карты внутри пакета прошивки

```sh
function install_navi_operation
{
    if [ -f "$NAVI_MAP_ARCHIVE"_aa ]; then    # ← только при наличии архива
        mount ${EMMC_NODE}p7 /mnt/inand
        mkdir -p $EMMC_MOUNT_PATH/Navngo
        cat "$NAVI_MAP_ARCHIVE"_* | tar -xzf - -C $EMMI_MOUNT_PATH
    fi
}
```

`p7` форматируется **всегда**, а карты возвращаются только если в пакете есть
`Navngo.tgz_aa` / `_ab` … То есть:

* карты были на внутреннем `p7` и их нет в пакете → **пропадут**;
* карты на отдельной карте в USB → **останутся на месте**.

## Что делать перед прошивкой

```bash
# 1. карты и лицензию — на отдельную карту в USB-порт (не в слот SD!)
# 2. config.ini — просто на всякий случай
adb shell su -c "cp /mnt/para_fw/config.ini /storage/usb1/keep/"

# 3. на время прошивки карту с картами лучше вынуть (см. риск выше)
```

После прошивки верни карту в USB — скрипт `/etc/install-recovery.sh`
(лежит в нашем образе) сам найдёт `*.nm7` на любом носителе, включая
`usb1`/`usb2`, и подмонтирует их в `/data/media/NavitelContent`.

## Ещё одна находка: предохранитель

Первым делом вызывается `fool_proofing_operation` — проверка, что прошивка
предназначена именно для этой модели. Значит случайно «чужая» прошивка не
начнёт писать разделы. Полезно: если прошивка не стартует — скорее всего
сработал этот предохранитель, а не сломалось железо.

## Про флешку после прошивки

`/fw_data` не удаляется, `boot.img` и `system.img` остаются на карте. Вреда нет
(следующий запуск всё равно заново создаёт разделы и пишет образы), но если
хочешь чистый цикл — после прошивки убери эти файлы, тогда ГУ не предложит
обновиться повторно.
