# 21. ADB с ноутбука: подключение к магнитоле

> ADB в прошивке **уже включён** — ничего доустанавливать в образ не нужно.
> Проверено по заводским файлам образа (см. раздел 21.7).

## 21.1 Что понадобится

| Что | Зачем |
|---|---|
| Ноутбук | любой: Windows, macOS, Linux |
| Кабель **USB-A — mini-USB** | у ГУ разъём mini-USB (не micro!) |
| ADB на ноутбуке | 15 МБ, ставится за пару минут |

**Важно про кабель.** Нужен именно mini-USB. И кабель должен быть
«полноценным» — многие кабели для зарядки не имеют линий данных,
с ними ноутбук магнитолу не увидит вообще. Если есть сомнения — берите
тот, которым раньше подключали телефон к компьютеру для передачи файлов.

## 21.2 Где разъём в машине

У Lifan X60 FL разъёмы ГУ (USB + mini-USB) выведены в бардачок или в
нишу у панели. Точное место смотрите в инструкции к машине — обычно
рядом с USB-портом для флешки.

**Осторожно:** тот USB-порт, куда вставляется флешка с музыкой, — это
**хост** (для флешек), к ноутбуку он не подходит. Нужен отдельный
разъём mini-USB, он помечен как USB-OTG или DEBUG.

## 21.3 Установка ADB на ноутбук

### Windows

1. Скачать **Platform Tools**: `https://developer.android.com/studio/releases/platform-tools`
2. Распаковать архив, например в `C:\platform-tools`
3. Открыть эту папку, кликнуть в адресной строке, набрать `cmd`, Enter
4. Проверить: `adb version` — должна показаться версия

Если `adb` не находится — запускать из папки, где лежит `adb.exe`
(пункт 3 это и делает).

### macOS

```bash
brew install android-platform-tools
adb version
```

### Linux (Ubuntu/Debian)

```bash
sudo apt install android-tools-adb
adb version
```

## 21.4 Подключение

1. **Включите магнитолу** (зажигание или ACC).
2. Соедините mini-USB ГУ с ноутбуком кабелем.
3. На ноутбуке:

```bash
adb devices
```

Ожидаемый ответ:

```
List of devices attached
0123456789ABCDEF	device
```

Серийный номер у каждого свой. Слово `device` — значит всё хорошо.

### Если написано `unauthorized`

Android 4.4 с `ro.adb.secure=1` спросит разрешение на экране ГУ:
появится окно «Разрешить отладку по USB?» с отпечатком ключа.
Нажмите **«Разрешить»** (галочку «Всегда разрешать» можно поставить).

Если окно не появилось или вы его случайно закрыли — выполните
`adb kill-server && adb devices` и переподключите кабель.

Файл с разрешениями живёт в `/data/misc/adb/adb_keys`. Он **стирается
при прошивке** (раздел `/data` форматируется), поэтому после каждой
перепрошивки разрешение спрашивается заново.

### Если список пуст

| Причина | Что делать |
|---|---|
| Кабель только для зарядки | взять другой кабель с линиями данных |
| Воткнут не тот разъём (USB-хост для флешек) | найти mini-USB на ГУ |
| На Windows не встал драйвер | Диспетчер устройств → найти устройство с восклицательным знаком → обновить драйвер → указать папку `platform-tools` (там есть `android_winusb.inf`) |
| Магнитола ещё грузится | дождаться рабочего экрана |
| ADB выключен в системе | см. 21.6, включить принудительно |

На Linux помогает добавить правила udev, иначе нужен `sudo`:

```bash
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="18d1", MODE="0666"' | sudo tee /etc/udev/rules.d/51-android.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

`18d1` — это Google; именно такой `idVendor` прописан в прошивке
(`init.el_imx6_solo_v2.usb.rc`).

## 21.5 Что делать дальше: первые команды

```bash
# кто я и что за система
adb shell getprop ro.product.model
adb shell getprop ro.build.version.release

# проверить, что приложения на месте
adb shell pm list packages | grep -E "navitel|torque"

# кнопки: прописан ли пакет в списке экрана
adb shell dumpsys package com.navitel | head -20

# фото экрана (сохранится на ноутбуке)
adb exec-out screencap -p > screen.png

# скопировать файл с ГУ
adb pull /data/local/tmp/mount_storage.log

# посмотреть логи в реальном времени
adb logcat -s ActivityManager:V AndroidRuntime:E
```

## 21.6 Если ADB не поднимается

В прошивке ADB включён, но если по каким-то причинам не работает,
есть два способа.

### Способ 1: через нашу панель (без перепрошивки)

На главном экране магнитолы нажмите **MirrorLink** → **«Для
разработчиков (ADB)»**. Откроются настройки разработчика Android,
где можно проверить и включить отладку.

### Способ 2: принудительно в образе

При сборке добавить свойство:

```bash
--set-prop persist.sys.usb.config=adb
```

Уже прописано в заводском `default.prop` (`persist.sys.usb.config=adb`),
поэтому обычно не требуется.

## 21.7 Что подтверждено по образу

Проверено разбором заводских файлов:

```
default.prop:
    ro.secure=1
    ro.debuggable=1
    persist.sys.usb.config=adb        ← ADB включён по умолчанию

init.rc:
    service adbd /sbin/adbd
    setprop ro.adb.secure 1            ← требует подтверждения на экране

init.el_imx6_solo_v2.usb.rc:
    sys.usb.config=adb      → idVendor 18d1, idProduct 4e42, start adbd
```

`ro.debuggable=1` означает, что отладка разрешена на уровне системы,
а `ro.adb.secure=1` — что при первом подключении ГУ спросит разрешение
(это нормально и правильно).

## 21.8 Частые вопросы

**Нужен ли root?** Нет. ADB работает от пользователя `shell`, для
чтения логов, установки приложений и `pull` файлов этого достаточно.
Root на этой прошивке есть (`ro.debuggable=1`), но через ADB он не
включается — для правки системного раздела нужен образ.

**Может ли ADB испортить прошивку?** Нет. Через ADB нельзя изменить
`/system` (раздел смонтирован только для чтения), а `adb reboot` просто
перезагружает магнитолу.

**Работает ли ADB по Wi-Fi?** На Android 4.4 — только если
предварительно подключиться по USB и выполнить `adb tcpip 5555`.
После этого:

```bash
adb connect 192.168.1.50:5555    # IP магнитолы в вашей сети
```

IP можно узнать на самой магнитоле: MirrorLink → Настройки Wi-Fi →
текущая сеть.

**Как отключить отладку?** Отключить кабель. Или на ГУ в настройках
разработчика выключить «Отладка по USB».
