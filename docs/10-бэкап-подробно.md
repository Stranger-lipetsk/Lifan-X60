# Бэкап перед прошивкой: подробная инструкция

> **Нужен ли он тебе?** Если заводская прошивка у тебя уже прошивалась успешно —
> она и есть откат, полный дамп не обязателен.
>
> Карты и лицензию **на отдельной карте в USB-порту** прошивка не трогает
> вовсе: она пишет только в eMMC (`mmcblk0`), а внешние накопители лишь
> монтирует. Достаточно держать их вне `p7` — подробный разбор заводского
> кода в [docs/11](11-что-делает-прошивка.md).

## Сначала — что бэкап реально спасает

Прежде чем что-то копировать, полезно понимать, что происходит при прошивке.
Я разобрал заводские скрипты из архива (`build_emmc.sh`, `general_conf.sh`,
`restore_system.sh`) — вот как оно работает на самом деле:

| Данные | Что делает прошивка | Нужен бэкап? |
|---|---|---|
| `config.ini` (VIN, настройки) | **Сама сохраняет** в `/fw_data/backup/` и возвращает после прошивки (`backup_operation` → `restore_operation`) | Нет, но пусть будет |
| Калибровка тача `tp_verinfo` | **Перегенерируется** из `/proc/gt9xx_ver` (`general_conf.sh` стирает старый и пишет новый) | Нет |
| `swap.img`, `data.tar` | Если они есть в составе прошивки — **автоматически** восстанавливаются в `p2` и `p5`, и снова кладутся в `p6/backup_image` | Нет |
| **Карты Navitel (`p7`)** | **Форматируется заново**: `newfs_msdos -F 32` | **Да** — если не в прошивке, карты пропадут |
| Установленные приложения, настройки Wi-Fi/BT, личные файлы | Стираются (разделы `p5`/`p6` создаются заново) | **Да**, если что-то важное |
| **Возможность откатиться на заводскую прошивку** | — | **Да, главное** |

**Вывод:** главная ценность бэкапа — не «спасти калибровку» (она восстанавливается
сама), а **иметь чем откатиться**, если новая прошивка не понравится или что-то
пойдёт не так, плюс сохранить карты Navitel.

---

## Что понадобится

| Нужно | Зачем | Проверка |
|---|---|---|
| SD-карта **FAT32**, ≥ 4 ГБ свободно | копии разделов | `df` в шаге 4 |
| USB-кабель (или флешка) | передать копию на компьютер | — |
| Компьютер с **adb** | запустить скрипт | `adb version` |
| Root на ГУ | читать разделы | он есть (`/system/xbin/su`) |

`adb` входит в [Android Platform Tools](https://developer.android.com/studio/releases/platform-tools)
— на Windows это папка `platform-tools`, `adb.exe` внутри (в Git Bash можно
добавить её в `PATH`).

---

## Шаг 1. Подключиться к магнитоле

Вставь SD-карту в слот (он работает — музыка с SD играет). Подключи ГУ к
компьютеру по USB и проверь:

```bash
adb devices
```

**Ожидаемый ответ:**
```
List of devices attached
0123456789ABCDEF        device
```

| Что видишь | Что значит | Что делать |
|---|---|---|
| `device` | всё готово | шаг 2 |
| `unauthorized` | на ГУ запрос доступа — подтверди | нажми «Разрешить» на экране ГУ |
| `offline` | связь зависла | `adb kill-server && adb devices` |
| пусто | отладка выключена или кабель «только зарядка» | см. ниже |

**Если список пуст.** Отладка по USB (`ro.debuggable=1` в прошивке включена,
так что чаще всего работает сразу). Если нет — включи вручную:
кнопка **MirrorLink** → **Для разработчиков (ADB)** → включить «Отладка по USB».
Если панель MirrorLink ещё не установлена — установи APK из
[docs/08](08-mirrorlink-vyhod-k-android.md).

**Если adb пишет `no permissions`** — попробуй `adb root`. В этой прошивке
`ro.debuggable=1`, поэтому `adb root` обычно срабатывает:

```bash
adb root
adb devices
```

---

## Шаг 2. Проверить root и разделы

```bash
adb shell su -c "id"
```

Должно быть `uid=0(root)`. Если `su: not found` или `Permission denied` —
дальше не идти, напиши мне.

Теперь посмотри разметку (это же попадёт в бэкап):

```bash
adb shell su -c "sfdisk -l /dev/block/mmcblk0"
```

Ожидаемо — 7 разделов:

| Раздел | Размер | Что внутри |
|---|---|---|
| `p1` | 8 МБ | `boot.img` (ядро + ramdisk) |
| `p2` | 256 МБ | `swap` |
| `p3` | 512 МБ | `system` |
| `p4` | — | расширенный (контейнер для p5–p7) |
| `p5` | 512 МБ | `data` |
| `p6` | 384 МБ | `el_data` → `/mnt/para_fw` (сюда `config.ini`, `tp_verinfo`, `backup_image/`) |
| `p7` | ~1.8 ГБ | FAT32, карты Navitel (`Navngo`, `.nm7`) |

## Шаг 3. Запустить бэкап

Скрипт `tools/backup-device.sh` (в репозитории) копирует разделы на SD-карту
в `/storage/extsd/lifan-backup/`.

```bash
adb push tools/backup-device.sh /data/local/tmp/backup.sh
adb shell su -c "sh /data/local/tmp/backup.sh"
```

### Три варианта по объёму

| Команда | Что копирует | Объём | Когда выбирать |
|---|---|---|---|
| `sh backup.sh --small` | `p1` (boot) + `p6` | ~400 МБ | быстро, минимум для откатa |
| `sh backup.sh` | `p1`, `p2`, `p3`, `p5`, `p6` | ~1.7 ГБ | **обычный выбор** |
| `sh backup.sh --with-navi` | всё + `p7` (карты) | ~3.7 ГБ | если карты Navitel нужны |

Пример полного:

```bash
adb shell su -c "sh /data/local/tmp/backup.sh --with-navi"
```

**Сколько ждать:** примерно 1 МБ/с на запись SD — `--small` около 7 минут,
полный 25–30 минут, с картами до часа. Не выдёргивай карту и не глуши ГУ.

### Что увидишь на экране

```
==========================================================
 Резервная копия Lifan X60 FL
==========================================================
[1/6] root: да
[2/6] eMMC: /dev/block/mmcblk0
[3/6] свободно на SD: 7400 МБ, нужно ~3700 МБ
[4/6] сохраняю сведения о системе
[5/6] таблица разделов
      U-Boot (boot0) ...
[6/6] копирую разделы
      p1 (boot, ~8 МБ) ...
      p2 (swap, ~256 МБ) ...
      ...
копирую файлы из p6 (para_fw) в читаемом виде
считаю контрольные суммы
```

Скрипт сам проверяет: root, наличие eMMC, что SD смонтирована, что хватает
места. Если что-то не так — **остановится с объяснением**, а не сделает
половину работы.

## Шаг 4. Проверить результат

```bash
adb shell ls -l /storage/extsd/lifan-backup
```

**Должно появиться:**

| Файл | Размер | Что это |
|---|---|---|
| `p1-boot.img` | 8 388 608 | загрузочный раздел |
| `p2-swap.img` | 268 435 456 | swap |
| `p3-system.img` | 536 870 912 | системный (заводской!) |
| `p5-data.img` | 536 870 912 | пользовательские данные |
| `p6-el_data.img` | 402 653 184 | para_fw |
| `p7-navi_maps.img` | ~1.8 ГБ | карты (только с `--with-navi`) |
| `boot0-uboot.img` | ~1 МБ | U-Boot |
| `para_fw/` | — | содержимое p6 файлами |
| `разделы.txt`, `система.txt`, `dmesg.txt` | — | сведения о системе |
| `backup.log` | — | ход копирования |
| `checksums-sha256.txt` | — | контрольные суммы |

Главное — **размеры**. Файл размером 0 или сильно меньше таблицы = копирование
не удалось, повтори.

> **Быстрая проверка через adb:**
> ```bash
> adb shell su -c "ls -l /storage/extsd/lifan-backup/*.img"
> ```

## Шаг 5. Забрать копию на компьютер

**Вариант А — через USB-кабель (быстрее всего):**

```bash
adb pull /storage/extsd/lifan-backup ./lifan-backup
```

**Вариант Б — вынуть SD-карту** и скопировать папку `lifan-backup` через
кардридер.

**Вариант В — через флешку в USB-порту:**

```bash
adb shell su -c "cp -r /storage/extsd/lifan-backup /storage/usb1/"
```

Объём 1.7–3.7 ГБ, по USB-кабелю это 5–15 минут.

### Проверь копию на компьютере

Обязательно — иначе можешь узнать о битом бэкапе ровно тогда, когда он нужен.

**Windows PowerShell:**
```powershell
cd lifan-backup
Get-FileHash p1-boot.img, p3-system.img, p6-el_data.img -Algorithm SHA256
```

**Git Bash / Linux / macOS:**
```bash
cd lifan-backup
sha256sum -c checksums-sha256.txt
```

Должно быть `OK` по каждому файлу. Если на устройстве не нашлось `sha256sum`
(на Android 4.4 его может не быть), сверь размеры — они в таблице выше.

## Шаг 6. Хранить в трёх местах

Бэкап на одной SD-карте бесполезен: SD умирают, теряются, и именно эту карту
ты возишь в машине.

| Место | Обязательно? |
|---|---|
| Компьютер (жёсткий диск) | **да** |
| Внешний диск / облако | **да** |
| SD-карта в машине | как удобство |

Приватный репозиторий на GitHub для 3.7 ГБ не подходит (лимит 100 МБ на файл,
рекомендованный репозиторий ≤ 1 ГБ). Если хочется в облако — Яндекс.Диск или
внешний диск.

## Как откатиться

### Способ 1: заводская прошивка (самый надёжный)

Возьми заводской архив и прошей как обычно:
**https://disk.yandex.ru/d/qJdjjeB8Aiq3Lg**

Порядок — в [docs/06](06-инструкция-модернизации.md). Вернётся ровно заводское
состояние.

### Способ 2: вернуть только раздел из бэкапа

Если что-то пошло не так точечно (например, испортил `p6`), можно вернуть
один раздел, не перепрошивая всё:

```bash
# ВНИМАНИЕ: затирает раздел p6 целиком
adb push p6-el_data.img /data/local/tmp/p6.img
adb shell su -c "dd if=/data/local/tmp/p6.img of=/dev/block/mmcblk0p6 bs=4M"
adb shell su -c "sync"
adb reboot
```

Так же возвращается `p1` (boot), `p3` (system), `p5` (data), `p7` (карты).
**Разметку (таблицу разделов) так не восстановить** — для этого нужна
прошивка целиком (способ 1).

### Способ 3: вернуть карты Navitel

Если карты пропали, но `p7-navi_maps.img` есть:

```bash
adb push p7-navi_maps.img /data/local/tmp/p7.img
adb shell su -c "dd if=/data/local/tmp/p7.img of=/dev/block/mmcblk0p7 bs=4M"
```

## Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `ОШИБКА: нужны права root` | скрипт запущен без `su` | `adb shell su -c "sh ..."` |
| `ОШИБКА: SD-карта не смонтирована` | карта не вставлена или не FAT32 | вставь карту, проверь `adb shell df` |
| `ОШИБКА: недостаточно места` | мало свободного на SD | освободи место или запусти с `--small` |
| `Permission denied` на `dd` | нет root | `adb root` или через `su` |
| `unauthorized` в `adb devices` | не подтвердил доступ | подтверди на экране ГУ |
| Файл `.img` получился 0 байт | кончилось место / карта отвалилась | проверь `backup.log`, повтори |
| Копирование идёт очень медленно | дешёвая SD-карта | нормально, жди; лучше класс 10 |
| `sha256sum: not found` | нет утилиты в Android 4.4 | сверяй размеры, суммы посчитаешь на ПК |

Лог всегда лежит в `/storage/extsd/lifan-backup/backup.log` — там видно, на
каком разделе что пошло не так.

## Короткая шпаргалка

```bash
# 1. подключиться
adb devices
adb root                    # если нужно

# 2. проверить root
adb shell su -c "id"

# 3. забрать скрипт и запустить
adb push tools/backup-device.sh /data/local/tmp/backup.sh
adb shell su -c "sh /data/local/tmp/backup.sh --with-navi"

# 4. проверить размеры
adb shell su -c "ls -l /storage/extsd/lifan-backup"

# 5. забрать на компьютер
adb pull /storage/extsd/lifan-backup ./lifan-backup

# 6. сверить суммы
cd lifan-backup && sha256sum -c checksums-sha256.txt
```
