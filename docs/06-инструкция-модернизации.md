# Модернизация ГУ: установка приложений, Torque Pro, новый Navitel

> **Выбранная стратегия — A:** оставляем штатный Android 4.4.2 и **весь заводской
> функционал** (камера заднего вида, радио, Bluetooth-звонки, климат, кнопки на руле).
> Меняем только программный состав `/system` и настройки. Ядро, загрузчик и МК не трогаем.

## Почему апгрейд Android не нужен

Обе задачи закрываются на текущей версии:

| Приложение | Требует | Наш Android 4.4.2 (API 19) |
|---|---|---|
| **Torque Pro** (`org.prowl.torque`) | Android **4.1+** | ✅ подходит |
| **Navitel Navigator 11.11.1128** | Android **4.4–5.1** | ✅ подходит |
| Navitel 12.x (последний) | Android 6.0+ | ❌ не встанет (и не нужен) |

Проверено на официальном APK с сайта Navitel: пакет **`com.navitel`**, `minSdk 14`,
`targetSdk 28`, архитектура armeabi — то есть **тот же пакет**, что и вшитый в прошивку
`Navitel-9.13.73`. Значит обновление ставится «поверх», настройки и лицензия сохраняются.

## Часть 1. Разрешить установку APK (5 минут, без перепрошивки)

Проверено по образу: `.odex`-файлов нет, `PackageInstaller.apk`, `DocumentsUI.apk`,
`DownloadProvider.apk` на месте — то есть система поддерживает обычную установку.
Ограничение только в оболочке `ElSettings` (она не показывает файловый менеджер).

### Способ 1 (проще всего) — установка по USB

1. Скачай APK на флешку/телефон и подключи к ГУ по USB.
2. На ГУ: `Настройки → Безопасность → Неизвестные источники` → **включить**.
3. Открой любой файловый менеджер. Если его нет — поставь **Total Commander**
   или **ES File Explorer** версии 4.x (последние версии требуют Android 5+).
4. Нажми на APK → «Установить».

### Способ 2 — через ADB (надёжный, сразу видно ошибки)

Нужен ноутбук, USB-кабель и Android SDK Platform-Tools.

```bash
adb devices                  # устройство должно появиться
adb install -r TorquePro.apk
```

Если `adb` не видит устройство — на ГУ включи `Настройки → Для разработчиков →
Отладка по USB` (ADB в прошивке уже активен: `persist.sys.usb.config=adb`,
`ro.debuggable=1`).

### Способ 3 — сразу вшить приложения в прошивку

Если хочется, чтобы приложения были «в системе» и переживали сброс — см. Часть 3.

## Часть 2. Torque Pro + OBD2-адаптер

**Что купить:** адаптер **ELM327 Bluetooth** (версия 1.5, не 2.1 — у 2.1 часто
урезанный набор команд). Для Lifan X60 подойдёт любой ELM327 с поддержкой
протоколов ISO 15765-4 CAN и KWP2000.

**Важный момент по Bluetooth.** В ГУ стоит связка **TI WL12xx + стек Bluesoleil**
(`/etc/bluesoleil`), а не стандартный BlueZ. Штатный стек заточен под гарнитуру и
телефонную книгу. Возможны два сценария:

1. **Хороший:** стек поддерживает SPP (Serial Port Profile) — Torque увидит адаптер
   в списке Bluetooth-устройств и подключится.
2. **Плохой:** SPP не проброшен через Bluesoleil — тогда Bluetooth-адаптер не заведётся.

Если случился второй вариант — есть обходные пути:

- **Wi-Fi адаптер ELM327** (например, Vgate iCar Pro WiFi): Torque подключается по
  TCP `192.168.0.10:35000`. Wi-Fi в ГУ штатный (WL12xx), режим клиента работает —
  адаптер создаёт свою точку доступа, ГУ к ней подключается. **Это самый надёжный путь.**
- **USB-адаптер ELM327** — зависит от наличия `ftdi_sio`/`cdc_acm` в ядре; в списке
  модулей их нет, так что менее вероятно.

**Настройка Torque после установки:**

1. `Настройки → Настройки OBD2 → Выбрать адаптер Bluetooth/WiFi`.
2. Профиль автомобиля: Lifan X60, двигатель 1.8 (Tianchuang/4G18-подобный),
   объём 1.8 л.
3. Если показания «замерли» — смени протокол вручную
   (`Настройки → Протокол OBD2 → ISO 15765-4 CAN, 11-bit, 500 kbps`).

## Часть 3. Обновление Navitel до 11.11.1128

**Скачать (официально, бесплатно):**
```
https://download.navitel.ru/Android/Navitel-v11.11.1128-Google-full.apk
```
(страница загрузок: https://navitel.ru/ru/downloads → «Совместимые версии для Android 5.1 и ниже»)

> Примечание: ссылка на 11.11.1128 с сайта в момент проверки отдавала 301/404 на
> зеркале `dl3.navitel.com`, а версия 9.13.73 скачалась нормально (188 МБ).
> Если 11.11.1128 недоступна — бери 11.11.1110 или 11.11.659 с apkpure
> (все они `minSdk 19`, то есть подходят к 4.4).

**Порядок:**

1. Установи APK как обычное приложение (Часть 1). Пакет тот же (`com.navitel`),
   поэтому система предложит **обновить** встроенную версию.
2. При первом запуске старый Navitel может ругаться на несовпадение версии карт —
   это нормально.
3. **Карты** лежат на отдельном разделе `p7` (`/storage/emmc_data` → `Navngo`).
   Navitel 11 использует тот же формат карт, что и 9.x, но каталоги могут отличаться:
   - старый: `/mnt/media_rw/emmc_data/Navngo`
   - новый:  `/mnt/media_rw/emmc_data/NavitelContent/Maps`
   Создай оба и положи карты (`*.nm7`) в оба места — программа подхватит нужный.
4. **Лицензия.** Встроенный Navitel шёл с лицензией на SD (`NavitelContent/License/
   NaviTel_Activation.txt`). При обновлении мажорной версии лицензию обычно нужно
   активировать заново по номеру устройства (он виден в `Настройки → О программе`).
   Если ключ не подходит — можно оставить 9.13.73 (она рабочая) и обновить только карты.

**Альтернатива без возни с лицензией:** оставить Navitel 9.13.73 как есть, а карты
обновить через **Navitel Navigator Update Center** на ПК (качает актуальные `.nm7`
на SD-карту).

## Часть 4. Сборка модифицированного system.img (если нужен «вшитый» вариант)

Инструмент: [`tools/build_system.py`](../tools/build_system.py)

```bash
# 1. Всегда сначала бэкап текущего состояния (см. tools/backup-device.sh)

# 2. Сборка образа: убираем тяжёлый стоковый Navitel, добавляем Torque,
#    меняем локаль на русскую
python3 tools/build_system.py \
    --fw "прошивка офиц. 2016г.rar" \
    --out out/system.img \
    --remove /priv-app/Navitel-9.13.73-large.apk \
    --add-apk TorquePro.apk:/app \
    --set-prop ro.product.locale.language=ru \
    --set-prop ro.product.locale.region=RU
```

Что скрипт делает: распаковывает `system.img` через `debugfs`, применяет правки,
собирает обратно ext4 ровно на 512 МиБ (размер раздела `p3`) и считает sha256.

**Рекомендуемый «лайт»-набор для первой сборки** (низкий риск, много свободного места):

```bash
--remove /priv-app/Navitel-9.13.73-large.apk      # 111 МБ, поставим свежий отдельно
--remove /app/IQQIService-Elead-International-20160105.1.apk   # 13 МБ, китайская клавиатура
--remove /app/BSEDemo.apk
--remove /app/EL830TAM1_GPIO_TEST_2015.01.01.01.apk
```

Освобождается ~125 МБ в `/system` — этого хватает на Torque, свежий Navitel и запас.

### Прошивка результата

1. Флешка **FAT32**, в корень положи:
   - `boot.img` (штатный, без изменений)
   - `system.img` (твой новый)
   - `u-boot.bin`, `MCU_FW.hex` — **штатные, не менять**
   - `sd_boot.img` — **штатный** (это загрузчик обновления, не трогать!)
2. Вставь флешку в ГУ, включи зажигание (двигатель не заводить).
3. Появится «LIFAN», затем «ANDROID», предложит начать прошивку — согласиться.
4. 5–7 минут, затем «вынуть карту» → `REBOOT`.

⚠️ Прошивка **пересоздаёт таблицу разделов** и стирает пользовательские данные.
Перед этим обязательно сохрани `p6/backup_image` (`swap.img`, `data.tar`) —
это штатный механизм откатa.

## Риски и что делать, если что-то пошло не так

| Симптом | Причина | Решение |
|---|---|---|
| ГУ не грузится, чёрный экран | битый `system.img` | `boot_mode_check.sh` сам развернёт `swap.img` с `p2`; иначе — перепрошивка штатным архивом |
| Загрузился, но пустой рабочий стол | удалил нужный APK оболочки | вернуть штатный `system.img`, повторить аккуратнее |
| Torque не видит адаптер | Bluesoleil без SPP | взять Wi-Fi ELM327 |
| Navitel просит ключ | мажорное обновление сбросило лицензию | вернуть 9.13.73, обновить только карты |
| Нет установки APK | выключены неизвестные источники | включить в настройках, либо `adb install` |

**Главное правило:** не менять `u-boot.bin`, `MCU_FW.hex` и `sd_boot.img`.
Всё остальное восстанавливается.

## Проверено на практике (результаты тестовой сборки)

Инструмент `tools/build_system.py` прогнан на реальном архиве прошивки.
Итог: образ собирается, монтируется и проходит `e2fsck` без ошибок.

| Параметр | Результат |
|---|---|
| Размер образа | **536 870 912 байт — ровно 512 МиБ** (раздел `p3`) |
| Файловая система | ext4, block 4096, inode 256, UUID свой |
| Фичи ext4 | `has_journal ext_attr resize_inode dir_index filetype extent flex_bg sparse_super large_file huge_file dir_nlink extra_isize` — **без `64bit` и `metadata_csum`** (иначе ядро 3.0.35 не смонтирует) |
| Владельцы | `root:root` (uid/gid 0) у всех файлов |
| Содержимое | 202 МиБ занято из 512 МиБ → **310 МиБ свободно** |
| `e2fsck -fn` | чисто, 1395 inode, битых блоков нет |
| Монтирование | успешно |
| Удалено | Navitel 9.13.73 (111 МБ), IQQI (13 МБ), BSEDemo |
| `build.prop` | `ro.product.locale.language=ru`, `ro.product.locale.region=RU` |
| `PackageInstaller.apk` | на месте — установка APK работает |

Важные технические выводы, которые уже учтены в скрипте:

1. **Размер строго 512 МиБ.** Свободного места в `p3` нет: раздел ровно 512 МиБ.
   Скрипт откажется собирать, если содержимое не влезет, и напечатает топ-10
   самых крупных файлов.
2. **Никакой `64bit`/`metadata_csum`.** Современный `mke2fs` по умолчанию включает
   `64bit`, и такое ядро 3.0.35 просто не смонтирует раздел. Скрипт перебирает
   варианты фич, начиная с максимально совместимого, и проверяет результат через
   `dumpe2fs`.
3. **`chown root:root` требует root.** В CI используется `sudo`; локально Docker/WSL.
   Если прав нет — сборка всё равно проходит, но владельцы останутся текущими
   (на 4.4 без SELinux это обычно допустимо, но лучше собирать от root).
4. **`su` в прошивке лежит в `/bin/bin/su`** (нестандартное место, потому что `/bin`
   в этой системе — папка с подкаталогами `bin/` и `sbin/`). Root уже есть.
5. `debugfs rdump` ругается на невозможность сменить владельца — это нормально
   и не влияет на результат.

### Как повторить сборку самому

```bash
# в Linux/WSL/Docker с e2fsprogs, 7z
sudo apt install e2fsprogs p7zip-full
python3 tools/build_system.py \
    --fw "прошивка офиц. 2016г.rar" \
    --out out/system.img \
    --remove /priv-app/Navitel-9.13.73-large.apk \
    --remove "/app/IQQIService-Elead-International-20160105.1.apk" \
    --remove /app/BSEDemo.apk \
    --set-prop ro.product.locale.language=ru \
    --set-prop ro.product.locale.region=RU
```

В репозитории есть готовый CI-прогон: `.github/workflows/build-test.yml`
(запускается пушем в `autoanalysis/buildtest.txt`), отчёты — в
`reports/build-log.txt` и `reports/build-strict.txt`.

### Предупреждение про локаль

В `framework-res.apk` **не найдено ресурсов русской локали**
(`res/values-ru/` отсутствует) — прошивка собрана как китайская/английская.
Смена `ro.product.locale.language=ru` даст русский **только в тех приложениях,
которые сами содержат русский перевод** (Navitel, Torque — да; системные
диалоги Android — нет). Полноценную русскую локаль в системном UI можно получить
только пересборкой `framework-res.apk` (aapt2), это отдельная задача.

### Если хочешь вариант с русской системной локалью

Скажи — соберу отдельно: потребуется правка `framework-res.apk` (добавление
`res/values-ru`), это увеличит размер на ~1–2 МБ и потребует тестирования.
