# Тестовая прошивка с файловым менеджером

## Релиз и контрольные суммы

Тестовый полный архив опубликован отдельным предварительным релизом:
https://github.com/Stranger-lipetsk/Lifan-X60/releases/tag/file-manager-test-20261105

- `lifan-file-manager-test.zip`, 278850943 байта,
  SHA-256 `4be81211994221e80e401ce712ce484b5320156902fff3707737b73e3945d17f`;
- `system.img` внутри архива, 377487360 байт,
  SHA-256 `a660f062716fd42d5a6185faec059f42675b3024304de7b81fac5d705cc88511`.

Workflow `42001239030` завершился успешно: проверены подпись APK для API 19,
файловая система до и после, точное добавление одного APK среди обычных файлов
и символьных ссылок и хеши всех файлов внутри ZIP. Эти проверки сборки сами по
себе **не являются тестом на устройстве**. Полный отчёт: `reports/file-manager-test-build.txt`.

Для проверки ZIP на Windows в PowerShell:

```powershell
Get-FileHash .\lifan-file-manager-test.zip -Algorithm SHA256
```

## Что это и важное предупреждение

Это **тестовая сборка**, а не исправление зависания загрузки. Пользователь
прошил её, открыл Amaze и нашёл файлы USB-флешки. Позже он сообщил об
успешной установке Torque и Яндекс Навигатора; работа OBD и ориентация экрана
остаются проблемными (подробности ниже). За основу `system.img` взят опубликованный пользователем образ
`рабочая-с-лаунчером`, SHA-256
`79df29ec1ea97fd2e1da605c9651c6e5cce9d05d79518ff8e3e7d1dd16553dba`.
В его копию добавлен один файл `/system/app/AmazeFileManager.apk`. Он должен
появиться в списке приложений Android под названием **Amaze**. Пользователь
увидел значок, открыл приложение и нашёл файлы USB-флешки; позже сообщил об
установке Torque и Яндекс Навигатора. Совместимость других APK не гарантирована.

**Быстрое окно выбора Home не исправлено.** Оригинальный system с лаунчером
один раз завис на «оптимизации» более 15 минут до Hibernate; позднее пользователь
сумел выбрать Home и этот же system загрузился. Причина неизвестна, новый образ
может снова зависнуть или не загрузиться. Не считать полученный образ безопасным
только потому, что автоматические проверки прошли.

## Содержимое полного архива

В полном архиве `lifan-file-manager-test.zip` должны быть ровно:

- `system.img` — копия опубликованного system с одним добавленным APK;
- `boot.img`, `sd_boot.img`, `u-boot.bin`, `MCU_FW.hex`, `backup/config.ini` —
  файлы из проверенного архива `stock/x60_2021.7z` энтузиаста.

Другие разделы текущей магнитолы опубликованы не были, поэтому соответствие
этих пяти файлов **текущей** установке не установлено. Наличие файлов в архиве
не доказывает, какие разделы прошивальщик реально перезапишет. В частности,
комплект содержит MCU: не запускать обновление, если непонятно, будет ли оно
записывать MCU и какие ещё разделы или данные могут измениться. Не подменять
`config.ini` чужими идентификаторами. Ни в коем случае не форматировать или
изменять SD с картами Navitel; использовать другой подходящий носитель и ранее
проверенный порядок обновления только если известны его последствия.

Сборка не меняет язык или часовой пояс. Сохранение текущей локали, UTC+3,
пользовательских данных и настроек при процедуре прошивки не гарантировано.
В результирующем system.img по проверке e2fsck осталось 1664 свободных блока из
92160 (при размере блока 4096 байт это около 6,5 МиБ); это свободное место
раздела system, а не внутренняя пользовательская память. Не добавлять другие
приложения в образ без отдельной проверки места.
Системные Home, Navitel, исходный Launcher2, `build.prop` и остальные обычные
файлы в system проверяются сравнением содержимого и символьных ссылок; все
метаданные inode и фактическое поведение устройства не проверяются. Исходный
набор и приложение идентифицируются по SHA-256; без успешного отчёта Actions
и отдельного релиза теста готового образа нет.

## О приложении

Amaze File Manager 3.5.3, опубликованный проектом TeamAmaze в релизе `v3.5.3`,
пакет `com.amaze.filemanager`, минимальный SDK 14, поддерживает русский в
ресурсах. Его APK проверен на подпись V1 для API 19; происхождение бинарного
файла — публичный релиз проекта, а не доказанная локальная пересборка из
исходников. Запрашивает доступ к хранилищу, сети и другие разрешения, перечислены
в `reports/file-manager-candidate.txt`; это приложение третьей стороны. Старый
V1 APK имеет предупреждения apksigner об отдельных неподписанных `META-INF`
записях; фактический APK дополнительно закреплён SHA-256
`2a9bc50c6672b1cb6efdfbd9bd9149bf280274e386305663163cc365abd393f3`.

По опубликованному исходному коду v3.5.3 `FileUtils.installApk()` на Android
ниже 7 использует `ACTION_VIEW` с MIME APK и `file://`. Штатный
PackageInstaller на Android 4.4 принимает схему `file` (в отличие от `content`);
это совместимые статические признаки, а не гарантия доступности конкретного
файла установщику; последующие результаты пользователя описаны ниже. Ссылка на исходник:
https://github.com/TeamAmaze/AmazeFileManager/blob/v3.5.3/app/src/main/java/com/amaze/filemanager/filesystem/files/FileUtils.java

## Порядок проверки, если пользователь решит прошивать

1. Сначала прочитать предупреждения выше и проверить опубликованные SHA-256 ZIP
   и system.img на странице **отдельного** тестового релиза. Убедиться, что
   доступен уже проверенный способ восстановления рабочего комплекта именно
   для этой магнитолы; если последствия записи неясны, не прошивать.
2. Не трогать SD с Navitel. Использовать только известную процедуру и отдельный
   носитель, предварительно распаковав ZIP; сам ZIP не доказан как формат,
   принимаемый прошивальщиком. Не считать запись только `system.img` безопасной
   или поддерживаемой без отдельной проверки.
3. На стоящем автомобиле наблюдать полный цикл: окно выбора Home → оптимизация →
   Hibernate → перезапуск → предупреждение → штатный рабочий стол. Если висит,
   записать время и точный экран; не делать предположений, что APK установился.
4. Если удалось попасть в список приложений Android, найти `Amaze`. Сначала
   проверить, открывается ли он и видны ли носители, не удаляя и не изменяя
   файлы или папки. Если приложение отсутствует или закрывается, сообщить об этом.
5. Только после успешного запуска отдельно проверить установку небольшого,
   известного пользователю APK, совместимого с Android 4.4.2, с уникальным именем
   пакета. Не выбирать Navitel и не обновлять установленный пакет: подписи могут
   не совпадать. Любое предложение включить установку из неизвестных источников
   или запрос разрешения читать отдельно; установка не выполняется без согласия.

## Результат первой проверки пользователем

Пользователь сообщил, что прошил тестовый комплект. На присланных фотографиях
виден список приложений Android со значком Amaze и открытый Amaze: отображается
`/storage/emulated/0` с папками. При выборе `usb2` открывается
`/storage/usb2` и отображается «0 folders and 0 files» / «Нет файлов».
Пользователь сообщает, что файлы видны через меню установки сертификатов.
На фото не подтверждена привязка `usb2` и носителя в выборе сертификатов к
одному и тому же физическому накопителю. Это не доказывает, что флешка пустая,
либо что отказ вызван правами: сначала следует уточнить путь и расположение.
На момент этой проверки повторная загрузка и установка APK ещё не были
подтверждены; более поздние результаты установки приведены ниже.

В исходниках Amaze 3.5.3 метод `MainActivity.getUsbDrive()` ищет в `/storage`
**первую** доступную для прохода запись с `usb` в имени и возвращает её; сам
метод не проверяет, что это нужный смонтированный накопитель. Поэтому подпись
`usb2` в меню сама по себе не устанавливает соответствие флешке. Ссылка:
https://github.com/TeamAmaze/AmazeFileManager/blob/v3.5.3/app/src/main/java/com/amaze/filemanager/ui/activities/MainActivity.java

Безопасная следующая проверка: на экране `/storage/usb2` нажать «Назад» один
раз и, если откроется `/storage`, сфотографировать список папок; не изменять
их содержимое и не извлекать SD с Navitel. Если приложение закроется или
покажет другую папку, сообщить, что произошло. Список поможет выбрать путь для
проверки, но сам по себе не определяет физический носитель. В выборе
сертификатов по-прежнему нельзя выбирать APK или устанавливать сертификат.

## Ошибка пункта OTG на Android 4.4.2

Пользователь сообщил, что SD с Navitel отключена; при подключении USB в Amaze
появляются пункты `usb2` и `OTG`. При выборе `OTG` приложение показывает экран
ошибки. На фотографии трасса содержит `java.lang.NullPointerException: USB OTG
root not set!`, `OTGUtil.getDocumentFiles(OTGUtil.java:82)` и
`LoadFilesListTask.listOtg`. Это сбой ветки OTG в Amaze, а не доказательство
повреждения USB, ошибки всей прошивки или пустой флешки.

В исходниках выбранного Amaze 3.5.3 `OTGUtil.getDocumentFiles()` явно выбрасывает
исключение при отсутствующем `usbOtgRoot`. `Drawer` запрашивает выбор корня через
`ACTION_OPEN_DOCUMENT_TREE` для этой ветки только на Android 5.0 и новее; на
Android 4.4 соответствующий запрос не выполняется в этом условии. Это объясняет
совместимость показанного сбоя с кодом, но не устанавливает, где смонтирована
конкретная флешка и почему `/storage/usb2` не показывает её файлы.
Источники:
https://github.com/TeamAmaze/AmazeFileManager/blob/v3.5.3/app/src/main/java/com/amaze/filemanager/utils/OTGUtil.java
https://github.com/TeamAmaze/AmazeFileManager/blob/v3.5.3/app/src/main/java/com/amaze/filemanager/ui/views/drawer/Drawer.java

Не повторять нажатие `OTG` и не отправлять отчёт для диагностики. Появление
пункта OTG не подтверждает режим USB-device или возможность подключения ADB.

## Файлы флешки найдены

Пользователь нашёл в Amaze каталог с файлами флешки и прислал фото: в заголовке
виден полный путь **`/mnt/media_rw/usb1`**, отображаются папки и имена APK.
Путь, который он использовал: кнопка перехода в корневую папку → `mnt` →
`media_rw` → `usb1`. SD с Navitel на момент предыдущей проверки была отключена.
Это подтверждает отображение имён файлов флешки в Amaze при данной конфигурации;
имя и путь монтирования могут измениться при другом подключении. Впоследствии
пользователь сообщил об успешной установке двух приложений; подробности см. ниже.
Пункт `usb2` ранее показывал пустую папку, а `OTG` вызвал сбой.

Не удалять работающий Navitel и не запускать его обновление, пока совместимость,
подпись и влияние на данные не проверены. Совместимость прочих показанных APK
с Android 4.4.2 и происхождение, включая модифицированный APK, не проверены.
Перепрошивка, форматирование и стирание пользовательских данных для просмотра
файлов не нужны.

## Результат установки приложений и новые проблемы

Пользователь сообщил об успешной установке Torque и Яндекс Навигатора после
перехода к файлам флешки в Amaze. Torque запущен, но соединение с OBD не
работает; пользователь связывает это с работой Bluetooth. Причина, состояние
сопряжения конкретного OBD-адаптера и поддержка нужного профиля пока не
установлены. Ранее телефон был сопряжён с магнитолой; это не подтверждает
работу Bluetooth-адаптера OBD в Torque. Не удалять сопряжения без необходимости.

На присланной фотографии открыт Яндекс Навигатор, интерфейс вместе с видимой
строкой состояния перевёрнут на 180 градусов относительно магнитолы.
Пользователь сообщил также об отсутствии интернета. Пока не уточнено,
сохраняется ли переворот после выхода из приложения и правильно ли работает
сенсор. Wi-Fi ранее был серым и не включался; связь с поведением навигатора
не установлена.

На экране навигатора виден пункт «Загрузка карт». Это основание проверить
возможность предварительно загруженных карт после появления интернета, но не
доказывает, что именно установленная версия строит маршруты без сети, что карты
уже загружены или что онлайн-функции работают офлайн. SD с картами штатного
Navitel не изменять и работающий Navitel не удалять.

Сборка не использует GitHub Actions artifacts и не перезаписывает прежние релизы.
