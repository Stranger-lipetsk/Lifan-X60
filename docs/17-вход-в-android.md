# 17. Как попасть в Android: HOME-режим вместо кнопки MirrorLink

> 02.11.2026. Кнопка MirrorLink теперь **нажимается** (сигнал доходит), но
> запуск не срабатывает: оболочка применяет к нажатию свою проверку. Ниже —
> почему так и как войти в Android надёжно.

## 17.1 Почему кнопка не запускает панель

Полная цепочка из кода `EL830LF01_Home.apk` (разбор baksmali):

```
нажатие иконки
  -> HomeService.goToApplication(PACKAGE_MIRRORLINK)
     -> сообщение MSG_GOTO_APPLICATION (0x192)
        -> HomeApp.gotoEleadApplication("com.fpt.mirrorlink.android")
```

И вот ключевое место в `gotoEleadApplication`:

```smali
:cond_15
  ... mEleadApplications.get(p1) -> mApp
  iget-boolean v6, v5, ...ApplicationInfo;->enable:Z
  if-nez v6, :cond_23
  move v1, v0            # bSuccess = false, выход
  goto :goto_a
  :cond_23
  ...
  :cond_a8                # обычный путь
  iget-object v6, v5, ...ApplicationInfo;->intent:Landroid/content/Intent;
  invoke-virtual {p0, v6, v7}, ...startActivityAsUser(...)
```

Две вещи, которые ломают запуск:

1. **Проверка `enable`.** Если на момент нажатия иконка ещё не была включена —
   метод просто возвращает `false`, ничего не запуская. Наш сигнал включает её
   только после того, как его получит `HomeService`, а порядок событий при
   загрузке не гарантирован.
2. **Запускается закэшированный интент.** Оболочка не ищет активность заново —
   она стартует `ApplicationInfo.intent`, который был построен при
   `loadEleadApplications()` на старте оболочки. Если пакет в тот момент не был
   виден (или версия ещё не установилась), интент пустой — стартовать нечего.

Отсюда поведение «нажимается, но ничего не происходит».

## 17.2 Что теперь работает вместо кнопки

| Способ | Как | Зависит от кнопки |
|---|---|---|
| **HOME** | кнопка «Домой» / перезагрузка Android открывает панель | нет |
| **Уведомление** | панель ставит уведомление «Открыть Android» | нет |
| **Внешнее действие** | `am start -a com.fpt.mirrorlink.android.START_ANDROID` | нет |
| Кнопка MirrorLink | остаётся, но ненадёжна (см. 17.1) | да |

`HOME` включён в манифесте (`activity-alias .HomeAlias`, `enabled="true"`).
При первом запуске Android спросит, чем открывать «Домой» — выбираем
**«Переключатель (Домой)»** и «Всегда».

## 17.2.1 Как вернуться в родной лаунчер

Родной лаунчер магнитолы — это `tw.com.elead.el830.home`, активность
`.Home` с категорией `HOME` (видно в манифесте `EL830LF01_Home.apk`).
Вернуться можно четырьмя способами, от простого к запасному.

**1. Кнопка в панели (самый быстрый).** В панели первая кнопка —
**«Магнитола (родной лаунчер)»**. Она запускает активность напрямую по
компоненту, поэтому не зависит от того, какой лаунчер выбран по умолчанию,
и не показывает диалог выбора.

**2. Снять с панели роль «Домой».** В панели есть кнопка
**«Вернуть «Домой» родному лаунчеру»**: она отключает `HomeAlias` и сразу
открывает магнитолу. После этого кнопка «Домой» снова ведёт в родной
лаунчер, без диалогов. Панель при этом остаётся установленной — зайти в неё
можно уведомлением или внешним действием.

**3. Настройки Android.** «Настройки Android» → **Приложения** → меню →
**Домой** (на 4.4 это `Settings → Home`) → выбрать магнитолу. Либо
«Приложения» → «Переключатель» → **«Очистить умолчания»**: Android снова
спросит, чем открывать «Домой», и выберете магнитолу.

**4. Совсем без Android — через ADB** (если панель недоступна):

```bash
# снять панель с роли домашнего экрана
adb shell pm disable com.fpt.mirrorlink.android/.HomeAlias

# вернуть обратно
adb shell pm enable com.fpt.mirrorlink.android/.HomeAlias
```

Полный откат — удалить панель совсем:

```bash
adb uninstall com.fpt.mirrorlink.android
```

После этого о кнопке MirrorLink и HOME-режиме не остаётся ничего: система
возвращается к заводскому поведению (кнопка MirrorLink снова серая).

## 17.2.2 Кнопка навигатора: как она появляется и как мы её вернули

Наблюдение с устройства подтвердило механику полностью. Кнопки на главном
экране — это **не настройки экрана**, а результат установки пакета:

1. оболочка держит жёсткий список пакетов (`initDefault_EL830CLF01()`);
2. при старте `loadEleadApplications()` проходит по списку и для каждого
   имени ищет приложение:

```smali
.method private findMainActivityForPackage(Landroid/content/Context;Ljava/lang/String;)Landroid/content/pm/ResolveInfo;
    ...
    const-string v4, "android.intent.category.LAUNCHER"
    invoke-virtual {v2, p2}, Landroid/content/Intent;->setPackage(Ljava/lang/String;)Landroid/content/Intent;
    invoke-virtual {v3, v2, v6}, Landroid/content/pm/PackageManager;->queryIntentActivities(...)
```

`setPackage(p2)` — имя пакета **точное**, из списка. Нет установленного пакета
`com.navitel` → нет записи в таблице → нет кнопки на экране. Именно поэтому
после удаления Navitel кнопка навигатора исчезла, а после установки нашей
панели под именем `com.fpt.mirrorlink.android` появилась кнопка MirrorLink.
Обе кнопки ведут себя по одному и тому же правилу.

**Отсюда решение.** Панель теперь собирается в двух экземплярах:

| Файл в образе | Пакет | Что даёт |
|---|---|---|
| `/system/app/switcher.apk` | `com.fpt.mirrorlink.android` | кнопка **MirrorLink** |
| `/system/app/navi.apk` | `com.navitel` | кнопка **навигатора** |

Второй экземпляр — та же панель, только собранная под именем `com.navitel`:

```bash
PACKAGE=com.navitel APK_NAME=navi.apk bash switcher/build.sh
```

Поэтому кнопка навигатора на главном экране появляется и открывает панель.
Оболочка осталась нетронутой, её код не патчился.

Побочное следствие: настоящий Navitel с этим образом поставить нельзя — имя
пакета занято. Если он понадобится, наш экземпляр удаляется одной командой
(`adb uninstall com.navitel`), и место освобождается.

## 17.3 Про кнопку навигатора и её «активность»

Наблюдение верное: кнопка навигатора активна, когда на SD есть карты. Это
буквально написано в оболочке:

```smali
.method public NaviIsExist()Z
    new-instance v0, Ljava/io/File;
    const-string v1, "/mnt/media_rw/extsd/NavitelContent"
    ... invoke-virtual {v0}, Ljava/io/File;->exists()Z
```

То есть кнопка навигатора проверяет **наличие каталога
`/mnt/media_rw/extsd/NavitelContent`** на SD-карте. Ни Navitel, ни его карты
не важны — важен сам каталог.

**Что из этого следует.** Появление кнопок на экране задаётся не конфигом, а
двумя вещами:

1. жёстко заданным списком пакетов (`HomeApp.initDefault_EL830CLF01()`) —
   `tw.com.elead.el830.radio`, `...elbluetooth.phone`, `...setup`,
   `...mediaplayer:SD`, `...mediaplayer:USB`, `...elbluetooth.music`,
   `com.fpt.mirrorlink.android`, `tw.com.elead.el830.avin`, `com.navitel`;
2. их наличием в системе — пакет есть в списке и установлен → кнопка есть.

Добавить своё приложение (Яндекс Навигатор) простым файлом в разделе
`/mnt/para_fw` **нельзя**: файл `config.ini` там содержит только
`sys.device.id=…` и строку версии, списка приложений в нём нет.

## 17.4 Реальный путь для Яндекс Навигатора

Самый дешёвый вариант — **не трогать оболочку вообще**: войти в Android
(HOME или уведомление) и запустить Яндекс Навигатор как обычное приложение с
рабочего стола. Ничего патчить не нужно, обновляется как обычный APK.

Если нужна именно кнопка на главном экране — это уже патч оболочки:
распаковать `EL830LF01_Home.apk` через apktool, добавить пакет
`ru.yandex.yandexnavi` в `initDefault_EL830CLF01()`, пересобрать и подписать.
Риски: оболочка подписана тестовым ключом платформы
(`C=US, O=Android, CN=Android, android@freescale.com`), пересборка apktool
ломает подпись, а `sharedUserId`/системных прав у оболочки нет, поэтому
подойдёт обычная подпись — но проверить это можно только на устройстве.

3. Дальше — рабочий стол Android, оттуда запускается что угодно.
