# Лабораторная репетиция полного архива

## Важно

Это **не готовая прошивка и не инструкция по прошивке**. Архив и образ из
описанной репетиции создаются только на временном GitHub Actions runner и не
публикуются. Их нельзя скачать или записать на магнитолу. Проверка содержимого
не доказывает загрузку устройства и не гарантирует сохранность данных.

Основа — полный ранее прошитый тест с Amaze `file-manager-test-20261105`, ZIP
SHA-256 `4be81211994221e80e401ce712ce484b5320156902fff3707737b73e3945d17f`;
внутри `system.img` SHA-256
`a660f062716fd42d5a6185faec059f42675b3024304de7b81fac5d705cc88511`.
Пользователь открывал в этой сборке Amaze и нашёл файлы USB. Это не проверка
новых изменений.

## Что проверяется

Workflow `.github/workflows/experiment-integrated-archive.yml` создаёт копию
system с помощью `tools/inplace_patch.py`, не пересоздавая ext4 через mke2fs.
В ней одновременно:

1. Заменяется системный `Navitel-large.apk` кандидатом Navitel 11 из
   `firmware/apks/com.navitel.apk`, SHA-256
   `96876415d8b4342952558fd30d6e11b0ca9355c802060c0a9740b6cc84fc4e1b`.
2. Меняется `EL830LF01_Home.apk`: добавляются две позиции для Amaze и панели.
3. В `Launcher2.apk` удаляется HOME-категория, чтобы он оставался доступен
   явным вызовом без участия в выборе HOME.
4. Добавляется отдельная панель `ru.lifanx60.panel`; Amaze остаётся без изменений.

Home и Launcher2 переподписываются публичными тестовыми ключами Freescale с
сертификатами, совпадающими с исходными. Публичность ключей — риск безопасности.
Для панели в этой репетиции используется **временный ключ, который не
сохраняется**; такая панель не предназначена для распространения и обновления.
Ключ будущего распространяемого варианта ещё не выбран.

Проверяются состав и хеши APK, подпись V1 для Android API 19, `e2fsck`, размер
system, права 0644, владелец 0:0 и SELinux-метка четырёх записанных файлов.
Сравниваются содержимое извлечённых файлов и цели символьных ссылок: допускаются
только перечисленные четыре отличия. Остальные метаданные inode целиком не
сравниваются. Затем временно собирается архив с шестью файлами: `system.img`,
`boot.img`, `sd_boot.img`, `u-boot.bin`, `MCU_FW.hex`, `backup/config.ini`.
Проверяются их хеши в новом ZIP и соответствие пяти файлов вне system исходному
ZIP. Полный текст результатов — `reports/integrated-full-archive-laboratory.txt`.

Репетиции Actions `42098116661` и `42098567154` завершились успешно: после
изменений в system осталось 4563 блока по 4096 байт. Во второй репетиции хеши
шести записей сверены с локальными исходными файлами, а пять файлов вне system
дополнительно напрямую сверены с исходным ZIP.

## Что ещё не доказано

- Реальная загрузка на ГУ, отсутствие окна выбора HOME с существующим `/data`,
  внешний вид и нажатия пунктов штатного кольца, работа радио и аудиомаршрутов.
  Отдельные методы Home и панель испытывались только в эмуляторе; подробности
  в `docs/39-ярлыки-home-и-загрузка.md`.
- Переход Navitel на другую подпись в уже установленной системе, его лицензия,
  формат карт и доступ к настоящей SD. Пользователь уточнил: штатный Navitel
  без SD с картами и лицензией неактивен и не запускается. Это не доказывает
  совместимость этих данных с Navitel 11. SD и карты не изменять и не
  форматировать. См. `docs/38-navitel-замена-и-сохранение-приложений.md`.
- Сохранность `/data`, лицензий, настроек и часового пояса при записи полного
  комплекта. Репетиция не меняет `build.prop` и файлы boot или MCU, но архив
  содержит MCU, и какие разделы перезапишет штатный обновлятор, не установлено.
- Причина прежнего зависания на оптимизации и поведение Hibernate. Штатный
  `hib_image_v2.sh` содержит форматирование внутреннего раздела; вручную его
  **не запускать**.

Позднее в `sd_boot.img` обнаружен скрипт, который при выполнении
переразмечает внутренний накопитель и форматирует, среди прочего, `p5` и `p7`;
наличие скрипта не доказывает его выполнение при конкретной прошивке. В этом
архиве нет пары `data.tar`/`swap.img`, используемой скриптом для условного
восстановления данных. Подробнее и с оговорками —
`docs/41-анализ-обновлятора-и-разделов.md`. **Сохранность данных не подтверждена.**

Следующий этап — проверить оставшиеся критические зависимости и определить
надёжную подпись панели и безопасный план проверки до публикации архива.
Никаких действий с устройством эта лабораторная репетиция не требует.
