> Torque Pro, а также вывести их кнопками на родной экран магнитолы.

| Шаг | Состояние |
|---|---|

## 18.2 Как оболочка строит кнопки

Кнопки не настраиваются файлом — они появляются по факту установки пакета
из жёсткого списка `HomeApp.initDefault_EL830CLF01()`:

```
tw.com.elead.el830.radio, ...elbluetooth.phone, ...setup,
...mediaplayer:SD, ...mediaplayer:USB, ...elbluetooth.music,
com.fpt.mirrorlink.android, ...avin, com.navitel
```

Дальше `loadEleadApplications()` для каждого имени ищет LAUNCHER-активность
через `queryIntentActivities(..., setPackage(имя))`. Нет пакета — нет кнопки.

Наш патч (`tools/patch_launcher.py`) делает три вещи:

1. **добавляет пакеты в список** — `ru.yandex.yandexnavi`, `org.prowl.torque`;
2. **снимает проверку `enable`** в `gotoEleadApplication` — иначе нажатие
   новой кнопки молча выходит (проверка заточена под MirrorLink и Navitel);
3. **задаёт интент** в ветке «незнакомый пакет» через
   `ApplicationInfo.setActivity(...)` — без этого у новой кнопки нет
   компонента для запуска.

Проверка на реальном APK оболочки:

```
пакет добавлен в список экрана: ru.yandex.yandexnavi
пакет добавлен в список экрана: org.prowl.torque
проверка enable снята (1 место)
в ветку по умолчанию добавлен setActivity
```

## 18.3 Подпись лаунчера: решено без ключа

Пересобранный apktool-ом APK подписан чужим ключом — Android 4.4 такой
системный пакет не примет. Приватного `testkey` у нас нет (в образе есть
только публичный сертификат), а ключ, которым подписан лаунчер, к тому же
не совпадает с сертификатом из `otacerts`.

Поэтому подпись **не трогаем вообще**. В сборке
`.github/workflows/build-full.yml`:

1. apktool распаковывает штатный `EL830LF01_Home.apk` и собирает обратно;
2. из результата берётся **только `classes.dex`**;
3. этот dex вставляется в **заводской** APK без сжатия (`zip -0`), затем
   файл выравнивается `zipalign`.

Итог: манифест, ресурсы и подпись — родные, изменился только код.
Dalvik на Android 4.4 подпись самого dex не проверяет, а подпись APK
остаётся в блоке подписи zip-контейнера, который мы не пересобирали.

Проверка на прогоне:

```
dex внутри (метод должен быть STORED):
  1852652  Stored  1852652  0%  classes.dex
размер: 4588177 -> 5708737 байт
сверка лаунчера с собранным: sha256 совпадает
в APK внутри образа: маркеры патча найдены
```

`keytool -printcert -jarfile` на новом файле ругается на «SHA1 digest error
for classes.dex» — так и должно быть: мы сознательно изменили содержимое,
не обновив подпись. Для системы это тот же файл, что и раньше.

**Риск и откат.** Если Android 4.4 всё же сверит подпись dex (в некоторых
сборках включён `ro.kernel.qemu`-подобный контроль не бывает, но проверка
дешёвая), лаунчер не запустится и экран останется пустым. Тогда:

- прошить предыдущий образ из релиза `lite-full` — вернёт рабочую оболочку;
- либо отключить в образе проверку dex (правится `services.jar`, для 4.4
  есть готовые патчи, но это отдельная возня).

Поэтому первый образ с патчем нужно проверить именно на запуск.

## 18.4 Блокер: сами APK

Автоматически скачать не удалось, проверено из CI:

| Источник | Ответ |
|---|---|
| 4pda.to (ваша ссылка) | **403** — нужна авторизация на форуме |
| apkpure.com | **403** — Cloudflare |
| apkmirror.com | страница версии отдаётся, ссылка на файл — нет |
| uptodown | страница версии 200, ссылка на файл — нет |
| Google Drive (ваши ссылки) | вместо файла приходит страница входа в аккаунт |

Google Drive отдаёт файл только владельцу или тем, кому выдан доступ
«всем, у кого есть ссылка». Проверить: открыть ссылку в режиме
инкогнито — если просит войти, доступ закрыт.

Как только APK окажутся в `firmware/apks/`, всё остальное соберётся само:

- файл с «avitel» в имени → `/priv-app`, остальные → `/app`;
- имя файла не важно, важен пакет внутри.

**Ограничение по месту.** После чистки в образе 124 МиБ. Примерно:
Navitel ~45 МиБ, Яндекс Навигатор ~30 МиБ, Torque ~15 МиБ — влезает.
Если Navitel 11 окажется «large»-сборкой под все экраны (как старая
9.13.73 на 106 МиБ), места может не хватить — тогда удалю ещё
`IQQIService` (12.7 МиБ) и `Launcher2` (11.7 МиБ), оболочка Elead от них
не зависит.

## 18.5 Что не сломается

- **Файловая система остаётся заводской** — правим через `debugfs`, как в
  `docs/15`. Пересборки через `mke2fs` нет.
- **Оболочка правится только в dex** — ресурсы и подпись не меняются.
- **Откат** — прошить предыдущий образ из релиза `lite-full`.

## 18.6 Порядок действий

1. Положить три APK в `firmware/apks/` и запушить.
2. Добавить секреты `LAUNCHER_KEY_B64` и `LAUNCHER_CERT_B64`.
3. Запустить «Полный образ (Navitel, Яндекс, Torque)».
4. Скачать образ из релиза `lite-apps` и прошить.
