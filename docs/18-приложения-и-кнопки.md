# 18. Приложения в образе и кнопки на главном экране

> 02.11.2026. Задача: вшить Navitel 11.11.1110, Яндекс Навигатор 6.40 и
> Torque Pro, а также вывести их кнопками на родной экран магнитолы.

## 18.1 Что уже сделано и что упирается

| Шаг | Состояние |
|---|---|
| Добавить пакеты в список главного экрана оболочки | **готово**, патч пишется и собирается |
| Снять заслонку `enable` при нажатии кнопки | **готово** |
| Задать интент для незнакомых пакетов | **готово** |
| Пересборка `EL830LF01_Home.apk` через apktool | **проверено**, собирается без ошибок |
| Подпись пересобранного лаунчера | **блокер**: нужен системный ключ |
| Скачать сами APK | **блокер**: автоскачивание закрыто (см. 18.4) |

## 18.2 Как оболочка строит кнопки

Кнопки не настраиваются файлом — они появляются по факту установки пакета
из жёсткого списка `HomeApp.initDefault_EL830CLF01()`:

```
tw.com.elead.el830.radio, ...elbluetooth.phone, ...setup,
...mediaplayer:SD, ...mediaplayer:USB, ...elbluetooth.music,
com.fpt.mirrorlink.android, ...avin, com.navitel
```

Дальше `loadEleadApplications()` для каждого имени ищет LAUNCHER-активность
через `queryIntentActivities(..., setPackage(имя))`. Нет пакета — нет кнопки.

Наш патч (`tools/patch_launcher.py`) делает три вещи:

1. **добавляет пакеты в список** — `ru.yandex.yandexnavi`, `org.prowl.torque`;
2. **снимает проверку `enable`** в `gotoEleadApplication` — иначе нажатие
   новой кнопки молча выходит (проверка заточена под MirrorLink и Navitel);
3. **задаёт интент** в ветке «незнакомый пакет» через
   `ApplicationInfo.setActivity(...)` — без этого у новой кнопки нет
   компонента для запуска.

Проверка на реальном APK оболочки:

```
пакет добавлен в список экрана: ru.yandex.yandexnavi
пакет добавлен в список экрана: org.prowl.torque
проверка enable снята (1 место)
в ветку по умолчанию добавлен setActivity
```

## 18.3 Блокер: подпись лаунчера

`EL830LF01_Home.apk` лежит в `/priv-app` и подписан **системным** ключом:

```
Owner: EMAILADDRESS=android@freescale.com, CN=Android, O=Android
SHA1:  3E:0C:AF:3D:79:9F:BA:EC:56:6F:AC:BE:1A:67:FB:25:0B:DE:FD:93
```

Это стандартный AOSP `testkey`. Пересобранный apktool-ом APK подписан быть
не может ничем другим: с чужой подписью Android 4.4 не обновит системный
пакет (а при прошивке образа — просто не загрузит его, и экран останется
пустым).

**Что нужно:** файлы `testkey.pk8` (приватный) и `testkey.x509.pem`.
Они открытые (AOSP), но в CI их надо передать секретами GitHub:

```
LAUNCHER_KEY_B64   — base64 от testkey.pk8
LAUNCHER_CERT_B64  — base64 от testkey.x509.pem
```

Получить base64:

```bash
base64 -w0 testkey.pk8      # -> LAUNCHER_KEY_B64
base64 -w0 testkey.x509.pem # -> LAUNCHER_CERT_B64
```

Без них сборка образа с патченым лаунчером не выпускается (скрипт пишет
«НЕТ КЛЮЧА» и не кладёт лаунчер в образ — остальное собирается).

## 18.4 Блокер: сами APK

Автоматически скачать не удалось — проверил из CI:

| Источник | Ответ |
|---|---|
| 4pda.to (ваша ссылка и темы) | **403** — закрыт для ботов, нужна авторизация |
| apkpure.com | **403** — Cloudflare |
| apkmirror.com | 404 на этот раздел |
| trashbox.ru | 200, но нужен поиск по странице |

Поэтому APK кладутся в репозиторий руками — в папку **`firmware/apks/`**
(инструкция внутри). Сборка берёт их оттуда:

- файл с «avitel» в имени → `/priv-app`, остальные → `/app`;
- имя файла не важно, важен пакет внутри.

## 18.5 Что не сломается

- **Файловая система остаётся заводской** — правим через `debugfs`, как в
  `docs/15`. Пересборки через `mke2fs` нет.
- **Оболочка правится только в dex** — ресурсы и подпись не меняются.
- **Откат** — прошить предыдущий образ из релиза `lite-full`.

## 18.6 Порядок действий

1. Положить три APK в `firmware/apks/` и запушить.
2. Добавить секреты `LAUNCHER_KEY_B64` и `LAUNCHER_CERT_B64`.
3. Запустить «Полный образ (Navitel, Яндекс, Torque)».
4. Скачать образ из релиза `lite-apps` и прошить.
