# 20. OBD-II, Bluetooth и Wi-Fi

> Проверено по образу и ядру 02.11.2026. Ниже — что реально можно сделать,
> а что нет, и почему.

## 20.1 Коротко

| Задача | Статус |
|---|---|
| Wi-Fi для навигатора | **есть в прошивке**, включается через панель |
| Bluetooth для Torque (ELM327) | **через встроенный модуль ГУ нельзя** |

Причина одна и та же, что и в остальном: у ГУ нет стандартного
Bluetooth-стека Android, а свой модуль умеет только три профиля.

## 20.2 Wi-Fi: работает штатно

Чип — **TI WiLink 18xx**, драйвер `wl12xx` вкомпилирован в ядро,
прошивка на месте:

```
/vendor/firmware/ti-connectivity/wl18xx-fw-4.bin      681 704 Б
/vendor/firmware/ti-connectivity/wl18xx-conf.bin        1 226 Б
/etc/wifi/wlconf/wl18xx-conf-default.bin                1 226 Б (копия)
/bin/wpa_supplicant, /bin/hostapd, /bin/dhcpcd           на месте
```

В `init.rc` подняты сервисы `wpa_supplicant`, `dhcpcd_wlan0`,
`iprenew_wlan0`, интерфейс `wlan0`.

### Как включить

1. На главном экране магнитолы — кнопка **MirrorLink** (наша панель).
2. **«Настройки Wi-Fi»**.
3. Включить Wi-Fi, выбрать сеть телефона, ввести пароль.

Требования к точке доступа телефона — в `docs/13`:

- **2.4 ГГц** (5 ГГц чип не видит вообще),
- WPA2-PSK (AES), не WPA3,
- имя сети латиницей, без пробелов.

### Подводный камень

`/etc/wifi/nvram.txt` и `/vendor/firmware/fw_bcm40181a2*.bin` — это
**остатки от базовой сборки под Broadcom AP6251**, они не используются.
Не пугайтесь: чип TI, прошивка TI.

## 20.3 Bluetooth: почему OBD-II не подключится

### Что стоит в системе

```
/etc/bluetooth/bt_vendor.conf:
    UartPort = /dev/ttymxc1
    FwPatchFilePath = /etc/firmware/
    FwPatchFileName = bcm20710a1.hcd

/lib/libbluelet.so        1 633 676 Б — ЗАКРЫТАЯ библиотека Elead
/etc/firmware/bcm20710a1.hcd  26 621 Б — прошивка чипа
```

Чип — **Broadcom BCM20710**, подключён по UART (`/dev/ttymxc1`).
Стек Bluetooth у Elead **свой, проприетарный** (`libbluelet.so`),
а не стандартный Android.

### Чего нет

Проверил по образу:

```
/lib/hw/bluetooth.default.so   — ОТСУТСТВУЕТ
/bin/hciattach, /bin/brcm_patchram_plus — ОТСУТСТВУЮТ
```

Стандартный пакет `com.android.bluetooth` (`Bluetooth.apk`) лежит в
`/app`, но **работать не может**: ему нужен
`lib/hw/bluetooth.default.so` — прослойка между Java-стеком Android и
чипом. Её в прошивке нет. В `init.rc` так и записано:

```
# No bluetooth hardware present
setprop hw.bluetooth 1
```

### Что умеет закрытая библиотека

По строкам внутри `libbluelet.so` видно профили:

| Профиль | Есть | Для OBD-II нужен |
|---|---|---|
| HFP (громкая связь) | да | — |
| A2DP / AVRCP (музыка) | да | — |
| PBAP / MAP (телефонная книга, SMS) | да | — |
| **SPP (последовательный порт)** | **да, встречается** | **именно он** |

SPP в библиотеке есть — на нём работают некоторые штатные функции.
Но **публичного Android API к нему нет**: приложения вроде Torque
обращаются к `BluetoothSocket` из стандартного стека, которого нет.

Поэтому диагностический адаптер ELM327 в паре «ГУ — OBD» через
встроенный модуль не заработает: система его просто не увидит как
Bluetooth-устройство с профилем SPP.

## 20.4 Что можно сделать для Torque

### Вариант 1 (рекомендую): USB-адаптер вместо Bluetooth

Torque одинаково хорошо работает с USB-адаптерами ELM327. Проблема в
другом: в ядре **нет драйверов USB-последовательных портов**.

```
поиск в ядре (kernel-gz0.bin.strings):
  ftdi_sio  0     ch341  0     pl2303  0     cp210x  0     usbserial  0
```

Это значит: адаптер на FTDI (FT232), CH340, PL2303, CP2102 **не
определится**. Нужен адаптер, который представляется как **USB CDC-ACM**
(класс `Communications and CDC Control`) — такие ядро 3.0.35
поддерживает штатно, без отдельных драйверов.

Как проверить перед покупкой: в описании адаптера должно быть
«CDC-ACM», «VCP без драйвера» или чип **STMicroelectronics /
Microchip MCP2200 / Silabs CP2102N в режиме CDC**. Либо брать тот,
про который прямо написано «works with Android without drivers».

Самый надёжный способ выбрать — подключить адаптер к ГУ и посмотреть:

```bash
adb shell dmesg | grep -i usb
adb shell ls /dev/ttyACM*
```

Если появился `/dev/ttyACM0` — Torque его увидит.

### Вариант 2: Bluetooth-адаптер через USB (USB-BT)

Тоже требует драйверов (`btusb` + `hci_uart`), которых в ядре нет
в нужной сборке. Тупик по той же причине.

### Вариант 3: собрать ядро с драйверами

Технически возможно: исходники Freescale i.MX6 + конфиг из текущего
ядра. Но это отдельный большой проект (кросс-компиляция, риск
окирпичивания при ошибке в ядре), и делать его ради OBD —
неоправданно. Если понадобится что-то ещё из USB (например, 3G-модем),
тогда имеет смысл.

### Вариант 4: телефон как шлюз

Torque на телефоне подключается к адаптеру, а на ГУ вы смотрите
показания через Wi-Fi. Это работает, но требует интернета и
сторонних приложений. Для постоянной приборки в машине — неудобно.

## 20.5 Что уже сделано в образе

Ничего из перечисленного образ не ломает:

- Wi-Fi остаётся рабочим, как в заводской прошивке;
- `libbluelet.so` и профили HFP/A2DP не тронуты — громкая связь и
  музыка с телефона работают;
- Torque установлен; когда появится подходящий адаптер (USB CDC-ACM),
  он его увидит.

## 20.6 Проверка на устройстве

Прежде чем что-то менять, стоит посмотреть, что реально происходит:

```bash
# Wi-Fi
adb shell dumpsys wifi | head -20
adb shell ip addr show wlan0

# Bluetooth: видит ли система адаптер
adb shell dumpsys bluetooth_manager | head -20

# USB: что подключено
adb shell lsusb 2>/dev/null || adb shell cat /sys/kernel/debug/usb/devices
adb shell dmesg | tail -40
```

## 20.7 Долгая первая загрузка после прошивки — это нормально

После прошивки магнитола показывает:

```
警告
Please wait for system optimization.
```

Это **не зависание и не ошибка**. Android пересобирает кэш приложений:
раздел `/data` отформатирован при прошивке, и системе нужно заново
разобрать каждый APK и скомпилировать его код в `data/dalvik-cache`.
Экран исчезнет сам, когда закончит.

### Почему сейчас дольше, чем раньше

| Причина | Вклад |
|---|---|
| Приложения новые и тяжёлые (Navitel 40 МБ, Torque 12 МБ) | основной |
| Оболочка `EL830LF01_Home.apk` — патченый dex на 5.7 МБ | заметный |
| Процессор i.MX6 Solo, одно ядро, 1 ГБ ОЗУ | замедляет всё |

Раньше первая загрузка шла «около минуты», потому что кроме заводских
приложений разбирать было нечего. Navitel — самый тяжёлый APK в системе,
и его 40 МБ дают основную часть времени.

### Сколько ждать

| Сценарий | Время |
|---|---|
| Обычная загрузка (после первой) | как раньше, ~1 минута |
| Первая загрузка после прошивки | 5–15 минут |
| Если через 20 минут экран не ушёл | есть проблема, см. ниже |

**Не выключайте зажигание во время оптимизации.** Если прервать, процесс
начнётся заново при следующем включении — данные не потеряются, но время
потратится снова.

### Как убедиться, что процесс идёт

Если подключён ADB:

```bash
adb shell ps | grep -E "dex2oat|installd|system_server"
adb shell top -n 1 | head
adb shell logcat | grep -iE "dex2oat|optimiz"
```

Живой `dex2oat` в процессах и загрузка процессора означают, что всё идёт
как надо.

### Если экран висит больше 20 минут

| Симптом | Что делать |
|---|---|
| Крутится, но ничего не меняется | подождать ещё 10 минут, затем перезагрузить |
| Перезагрузили — снова оптимизация | норма, продолжится с того же места |
| Циклическая перезагрузка с логотипом Lifan | откат на `lite-full`, см. `docs/15` |

Откат всегда возможен: заводской образ и предыдущие сборки лежат в
релизах GitHub.
